# 体系：运行时组装（runtime）

> 改这里如果：**你要让世界带代码、要区分「声明式」和「可执行」、或者要改规则从哪来**。

## 一句话

**激活一个世界 = 组装一个运行时规则表。**

```
引擎规则（core.*）
+ base 规则（base.*）
+ 世界的声明式内容（触发器 → 编译成一条通用规则）
+ 世界的可执行代码（冷加载模块，注册自己的规则）
= 这个世界的规则表
```

## 两种作者层

| | 声明式（declarations） | 可执行（executable） |
|---|---|---|
| 形态 | 数据：参数 / 效果列表 / 触发器 | JS 模块 |
| 谁写 | **AI 默认写这个** | 人（或人授权的 AI） |
| 生效 | 可热加载 | 世界激活时冷加载 |
| 表达力 | 1–3 级（见 agent.md 阶梯） | 4 级 |
| 安全 | 高（没有代码） | 取决于信任 |

**区别是「受限 vs 不受限」，不是「差 vs 好」。** 文档里别叫「弱代码」。

## 关键实现：两层汇成同一种规则

```
声明式触发器
   ↓ 编译
{ tag: "world.trap_spike", handler: 通用触发器求值器 }
```

**编译出来就是一条普通规则。** 运行时只认一种规则——冲突检测、溯源、日志、禁用开关全部共用。

**如果声明式自带执行器，早晚两套语义会不一致。**

## 可执行代码的边界

```json
// pack.json
"code": ["runtime/index.js"],
"trust": "local"
```

```js
export default function (ctx) {
  ctx.defineRule({
    tag: "mymod.slash",
    handle: (params, view) => ({ ok: true, effects: [...] }),
  });
}
```

- **冷加载**：世界激活时 `import()`，不热更；
- **溯源**：每条规则记「来自哪个包、哪个文件」；
- **确定性**：用 `ctx.roll(tag)`，禁用 `Math.random` / `Date.now` / 网络（约定 + 以后静态检查）；
- **API 冻结**：`ctx` 发出去就不再改，扩展只加不改。

## 信任边界

```
本地自己写的     直接跑（就是玩家自己的 mod）
下载别人的世界   要么明确警告「含代码」，要么以后进沙箱
```

**启动器要给「含代码的世界」打标记。**

## 冲突

两个包注册同一个 tag → 按 `world.json` 的 `onConflict` 处理（已有策略）：

```
error     直接失败，报出两个来源
warn      后者覆盖，日志警告
override  后者覆盖，静默
```

## 和场景/感知的关系

```
场景   运行时决定「现在能做什么」
感知   运行时决定「能看到什么」
AI     /api/ability = 当前场景的命令表 + 可用规则
```
