# 公司与剧院：双层架构

> 结论：**游戏公司负责「造」，剧院负责「演」。**
> 两者共用一份「剧本」；公司把剧本做成数据，剧院在规则内演出。
> 相关：`docs/base/ai-roles.md`（职责树）、`docs/base/ai-bridge.md`（交接协议）。

---

## 1 为什么是合体

```
只有游戏公司
  → 能把世界造出来，但运行时是死的：NPC 只会按表执行

只有剧院
  → 演出很活，但没有生产线：资产、版本、QA、许可全缺

公司 + 剧院
  → 离线造「剧本 + 布景 + 演员表」
  → 运行时按剧本演出，允许在边界内即兴
```

**一句话：公司保证「可交付」，剧院保证「活」。**

---

## 2 两个时钟

```
制作时钟（离线）        天 / 周
  写剧本、画布景、排角色、QA、批准

演出时钟（运行时）      tick / 秒
  舞台状态、演员上场、提示触发、观众反应
```

**两个时钟通过「剧本」交接，运行时不能改剧本。**

---

## 3 合体树

```
制作公司（离线）
├─ 创意总监 / 制作人        人
├─ 世界与舞台设计           L1
│     地图、势力、生态、舞台结构
├─ 剧作家                   L2
│     剧情、任务、对话、分支
├─ 美术 / 服装 / 道具       L4
│     图集、立绘、图标、动画
├─ 排练 / QA                L5
│     校验、回归、许可、评分
└─ 批准                    人

        │  交接：剧本 + 布景 + 演员表
        ▼

剧院（运行时）
├─ 舞台监督                 L0 引擎
│     空间、规则、tick、效果、存档
├─ 导演                     L6（可选 AI）
│     节奏、场面调度、氛围；不改剧情
├─ 演员                     L3（NPC / 对话 AI）
│     台词、选项、即兴；不改状态
├─ 提词员                   静态剧本 / 兜底
└─ 观众                    玩家
```

## 4 职责对照

| 角色 | 阶段 | 权力 | 输入 | 输出 | 禁止 |
|---|---|---|---|---|---|
| 人（制作人/总监） | 制作 | 决策/批准 | 全部 | 方向、批准、回滚 | — |
| L1 世界与舞台设计 | 制作 | 提议 | 种子、设定、约束 | 世界/舞台提案 | 改运行时 |
| L2 剧作家 | 制作 | 提议 | 世界、角色、语气 | 剧本、任务、对话 | 改数值/地图 |
| L4 美术/服装/道具 | 制作 | 产出 | brief、风格指南 | 资产批次 | 改玩法 |
| L5 排练/QA | 制作 | 否决 | 产物 + 契约 | 通过/拒绝/问题 | 改产物 |
| L0 舞台监督（引擎） | 演出 | 提交 | 剧本、输入 | 状态变化、事件 | 被 AI 绕过 |
| L6 导演（可选） | 演出 | 调度 | 剧本、舞台状态、观众状态 | 场景切换、氛围、节奏 | 改剧情/数值 |
| L3 演员 | 演出 | 措辞 | 当前场景、可见事实 | 台词、choiceId | 给 Effect |
| 提词员 | 演出 | 兜底 | 剧本 | 静态台词 | — |
| 观众（玩家） | 演出 | 行动 | 舞台 | 输入 | — |

## 5 剧本契约（草案）

剧本是公司与剧院的唯一交接物：

```json
{
  "id": "play.swamp",
  "acts": [
    {
      "id": "act1",
      "scenes": [
        {
          "id": "scene.ambush",
          "cast": ["npc.bandit_1", "npc.bandit_2"],
          "cues": [
            { "at": 0, "effect": "spawn", "ref": "npc.bandit_1" },
            { "at": 4, "effect": "broadcast", "tag": "play.ambush_start" }
          ],
          "branches": [
            { "when": "player.flees", "to": "scene.escape" },
            { "when": "player.fights", "to": "scene.battle" }
          ],
          "improv": {
            "allowed": ["taunt", "banter"],
            "forbidden": ["kill_player", "give_item"]
          }
        }
      ]
    }
  ],
  "roles": {
    "npc.bandit_1": { "template": "bandit", "actor": "L3" }
  }
}
```

关键字段：

```
acts / scenes        幕与场
cast                 演员表
cues                 提示：第几拍做什么
branches             分支条件
improv               即兴许可：能说什么、不能做什么
roles                谁演、用哪个模板
```

## 6 运行时 AI 的边界

```
L6 导演
  只能：切场景、调节奏、选氛围、叫停/加戏（在剧本允许的分支里）
  不能：改数值、给物品、写新剧情

L3 演员
  只能：说台词、在已有选项里排序
  不能：产生 Effect、改世界

所有 AI 决策都写进演出记录
  → 回放可复现
  → 离线用静态剧本兜底
```

**确定性不靠「AI 永远一样」，靠「决策被记录」。**

## 7 和现有代码的映射

| 剧院概念 | 现有实现 |
|---|---|
| 舞台 | `Space`（格子、地形、占用者） |
| 幕 / 场 | `SceneStack` |
| 演员 | 实体 + 模板 |
| 舞台监督 | `Store` / `applyEffects` / tick |
| 提示（cue） | 规则 + 事件 + `core.pending` |
| 排练 | 测试 / `tools/play.mjs` |
| 录播 | 存档 + 事件日志 |
| 提词员 | 静态对话脚本 |
| 观众 | 玩家输入 |

**已经有一半了：缺的是「剧本」这层数据，以及 L6 导演的接入点。**

---

## 8 和纯公司 / 纯剧院的差异

```
比纯公司多：
  运行时表演层、观众、即兴、演出记录

比纯剧院多：
  制作流水线、资产版本、QA、许可、批量生成

代价：
  多一层「剧本」数据；运行时 AI 必须被记录；离线要能兜底
```

---

## 9 落地顺序

```
1  把「剧本」定义成数据（先只支持 场景 + 提示 + 分支）
2  运行时按剧本走，AI 只做台词（L3）
3  加 L6 导演的只读接口：看舞台、选下一个场景
4  演出记录：AI 决策写进日志
5  QA（L5）审剧本与资产
6  L1/L2 离线生成剧本提案
```

**先让「静态剧本」跑通，再让 AI 上台。**
