# AI 职责树（对照游戏工作室）

> 参考：典型游戏工作室的职责划分（创意总监 → 设计/美术/工程/QA）。
> 目的：把「AI 能做什么」对齐到公司里的岗位，避免一个 AI 同时当导演、编剧、美术和 QA。
> 协议：`docs/base/ai-bridge.md`。
> 架构：`docs/base/studio-theater.md`（公司 + 剧院双层）。

---

## 1 参考：一个游戏工作室

```
制作人 / 创意总监
├─ 设计
│  ├─ 主设计师
│  ├─ 世界设计师        地图、势力、生态
│  ├─ 系统设计师        数值、战斗、经济
│  ├─ 叙事设计师        剧情结构、分支
│  ├─ 任务设计师        任务链、奖励
│  └─ 内容设计师        NPC、物品、事件
├─ 美术
│  ├─ 美术总监          风格、调色板、审核
│  ├─ 概念美术          气氛图、角色概念
│  ├─ 2D / UI 美术      立绘、图标、界面
│  └─ 动画师            帧动画、骨骼
├─ 工程
│  ├─ 技术总监
│  ├─ 引擎 / 工具
│  └─ 玩法程序
├─ 音频
│  └─ 作曲 / 音效
├─ QA
│  └─ 测试、回归、验收
└─ 本地化 / 社区
```

关键：**职位不是按「用了什么工具」分，是按「对产物负什么责」分。**

## 2 对应到我们的 AI 树

```
引擎（不是 AI）
│  唯一提交权、验证、确定性
│
├─ L0 内核
│     规则、状态、存档
│
└─ AI 交接（提议 / 产出，不提交）
   │
   ├─ L1 世界导演            ≈ 创意总监 + 世界设计师
   │     输出：世界提案、势力、事件、地图意图
   │
   ├─ L2 内容作者            ≈ 叙事 / 任务 / 内容设计师
   │     输出：NPC、对话脚本、任务、物品描述
   │
   ├─ L3 对话演员            ≈ 编剧 + 表演（运行时）
   │     输出：台词、选项排序（不碰状态）
   │
   ├─ L4 素材工坊            ≈ 美术总监 + 概念 + 2D/UI
   │     输出：图、图标、立绘、动画帧
   │
   └─ L5 审计                ≈ QA + 美术评审
         输出：通过 / 拒绝 / 评分 / 问题清单
```

**制作人 = 人（你）**：定方向、拍板、批准导入。

## 3 对照表

| 工作室岗位 | 我们的角色 | 权力 | 输入 | 输出 | 绝对不能做 |
|---|---|---|---|---|---|
| 创意总监 | 人（作者） | 决策 | 全部 | 方向、批准 | — |
| 世界设计师 | L1 世界导演 | 提议 | 种子、设定、约束 | 世界/势力/事件提案 | 直接改世界 |
| 叙事/任务/内容设计 | L2 内容作者 | 提议 | 区域上下文、NPC 名单 | NPC/任务/对话数据 | 改数值/地图 |
| 编剧（运行时） | L3 对话演员 | 措辞 | 当前场景、可见事实 | 台词、choiceId | 给 Effect、改状态 |
| 美术总监 | L4 素材工坊（风格） | 提议 | brief、风格指南 | 风格约束、参考图 | 改玩法 |
| 概念/2D/UI 美术 | L4 素材工坊（绘制） | 产出 | 具体 brief | 图集、图标、动画帧 | 改玩法 |
| 引擎/工具程序 | 引擎（L0） | 提交 | 代码、数据 | 可运行世界 | — |
| QA | L5 审计 | 否决 | 产物 + 契约 | 通过/拒绝/问题 | 改产物 |
| 制作人 | 人（你） | 批准 | 全部 | 导入/回滚 | — |

## 4 和工作室的差异

```
1  没有「制作人 AI」
     排期、取舍、品味由人做；AI 只提议。
2  美术总监和画师合并成 L4
     第一版不拆；需要时再分 L4a（定风格）/ L4b（画）。
3  QA 只审契约，不审「好不好玩」
     好玩由人判断；审计管 schema、引用、许可、尺寸。
4  程序没有 AI 角色
     引擎确定性是底线；AI 不写运行时代码。
5  音频 / 本地化暂缺
     以后加 L6 音频、L7 本地化，不影响现有树。
```

## 5 信息分级（谁能看什么）

```
P0 公开      设定、风格指南、术语表
P1 内部      世界种子、势力关系、未公开事件
P2 玩家私有  背包、位置、已解锁情报
P3 禁止      密钥、存档路径、其他玩家数据
```

| 角色 | 可见 | 说明 |
|---|---|---|
| L1 世界导演 | P0 + P1 | 需要全局才能提世界 |
| L2 内容作者 | P0 + 局部 P1 | 只给当前区域 |
| L3 对话演员 | P0 + 当前场景 + 可见 P2 | 不给隐藏 P1 |
| L4 素材工坊 | P0 | brief 里不放剧情秘密 |
| L5 审计 | 产物 + 契约 | 不需要世界秘密 |

## 6 权限阶梯

```
读   → 所有角色
提议 → L1 / L2 / L4
措辞 → L3（只有文本）
否决 → L5
提交 → 只有引擎
批准 → 只有人
```

**AI 永远拿不到 Store，也拿不到 Effect 的直接写权。**

## 7 队列里怎么体现

`request.json`：

```json
{
  "role": "world-director",
  "clearance": ["P0", "P1"],
  "authority": "propose",
  "brief": "生成一片沼泽区域的势力与事件",
  "delivery": { "inbox": "artdrop/inbox" }
}
```

- 外部 AI 只认领 `role` 匹配、`clearance` 覆盖的任务。
- 回执带 `role`，审计可追溯。
- 一个 AI 可以注册多个 role，但每个请求只属于一个 role。

## 8 第一版落地

```
必做    L1 世界导演（文字提案）
        L4 素材工坊（图）
        L5 审计（契约校验）
可选    L3 对话演员（只改写台词）
以后    L2 内容作者（NPC/任务数据）
```

**先证明「提案 → 校验 → 人批准 → 提交」这条循环，再扩角色。**
